# HTTP API ConfManager

JSON API доступно на том же адресе, что и веб-интерфейс. Точные модели и примеры отображаются в `/docs` и `/openapi.json`. Пароли и хеши не возвращаются в ответах.

## Авторизация и права

`POST /auth/login` принимает `application/x-www-form-urlencoded`: `username=email` и `password`. Ответ: `access_token` и `token_type=bearer`. Для защищённых запросов передавайте `Authorization: Bearer <token>`. JWT содержит sub (email), iat и exp. Текущие права определяются по БД; произвольное поле role в JWT не даёт прав оргкомитета. Новые пароли хешируются Argon2; существующие bcrypt обновляются при успешном входе.

| Метод и адрес | Доступ | Вход и результат |
| --- | --- | --- |
| `POST /participants` | Без входа | full_name, email, password, необязательная organization; участник, 201 |
| `POST /auth/login` | Без входа | Форма username/password; JWT, 200 |
| `GET /auth/me` | Вход | Свой профиль и текущая роль, 200 |
| `GET /participants/{id}` | Сам участник или оргкомитет | Профиль участника, 200 |
| `POST /applications` | Вход | topic, необязательный participant_id; новая заявка, 201 |
| `GET /applications` | Вход | Собственные заявки либо все для оргкомитета, включая взнос, 200 |
| `PATCH /applications/{id}/status` | Оргкомитет | status; изменённая заявка, 200 |
| `POST /fees` | Оргкомитет | application_id и amount; взнос, 201 |
| `POST /fees/{id}/pay` | Оргкомитет | Отметить оплату принятой заявки, 200 |
| `GET /health` | Без входа | status=ok и время UTC; без запроса к БД |
| `GET /ready` | Без входа | status=ready после SELECT 1; 503 при недоступной БД |
| `GET /version` | Без входа | version=0.1.0 |

В `POST /applications` без participant_id автором становится вошедший участник. Указание чужого id разрешено только оргкомитету. Взнос имеет статусы unpaid/paid; статус заявки — new/under_review/accepted/rejected. После оплаты статус заявки остаётся accepted. Повторная оплата идемпотентна и сохраняет paid_at.

## Валидация и ошибки

ФИО и непустая организация — до 200 символов, тема — до 500; пробелы по краям удаляются. Пустую организацию передавайте как null либо не передавайте. Email валидируется и нормализуется в нижний регистр. Пароль содержит 12–128 символов и не состоит только из пробелов. Сумма положительная, конечная, до 9 999 999 999,99 включительно, до двух десятичных знаков. Идентификаторы в JSON положительные. Неизвестные входные поля запрещены.

| Код | Причина |
| --- | --- |
| 400 | Email уже занят, взнос уже есть, заявка не принята для оплаты, попытка отклонить оплаченную заявку |
| 401 | Нет входа, неверный пароль, недействительный/просроченный JWT, участник удалён |
| 403 | Чужие данные либо требуется оргкомитет |
| 404 | Допустимый по правам, но отсутствующий участник, заявка или взнос |
| 409 | Конфликт целостности при записи |
| 422 | Некорректные поля, сумма, email или статус |
| 503 | БД временно недоступна; подробности подключения не возвращаются |

После входа в Swagger нажмите Authorize и выполните сценарии из [acceptance.md](acceptance.md). В браузере JWT хранится в sessionStorage текущей вкладки и удаляется при выходе. Для внешнего развёртывания нужен HTTPS; в локальной ЛР1 используется loopback HTTP.
