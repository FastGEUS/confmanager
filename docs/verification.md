# Проверка изменений

Из корня проекта в активированном окружении установите `requirements-dev.txt` и выполните `python -m app.manage verify`. Make-эквивалент — `make verify`. Команды доступны без чтения `.env`; тесты используют отдельную SQLite в памяти и случайный тестовый ключ.

| Проверка | Команда | Требование |
| --- | --- | --- |
| Зависимости | `python -m pip check` | Нет конфликтов зависимостей |
| Python lint | `python -m ruff check .` | Нет нарушений E, F, I |
| Форматирование | `python -m ruff format --check .` | Нет файлов с требуемым переформатированием |
| Анализ безопасности | `python -m bandit -r app -q` | Нет необъяснённых находок |
| Автотесты | `python -m pytest -q` | Все 54 теста проходят |

Тесты проверяют регистрацию, нормализацию email, пароль, обновление bcrypt, права на чужие заявки, изменение и отзыв прав, подделку роли в JWT, сроки токенов, валидацию, идемпотентность оплаты, запрет отклонения оплаченной заявки, ответы при сбое БД, конфигурацию и команды создания оргкомитета. Изоляция БД исключает запись в пользовательские данные.

В app/manage.py оставлены два точечных исключения Bandit: B404 при импорте subprocess и B603 у subprocess.run. Команда verify запускает только статические списки модулей и аргументов текущим Python, с shell=False и check=True; пользовательские строки в команды не передаются. Общие проверки не отключены, список исключений не вынесен на весь проект. Любое изменение этой команды требует повторного анализа исключений.

При проверке 5 октября 2026 года весь набор прошёл на Python 3.12.14 и 3.14.7 с зафиксированными прямыми зависимостями. Предупреждение Starlette о будущем переходе TestClient с httpx на httpx2 не подавляется. Оно не означает сбой API. Совместимость PostgreSQL и системного сервиса должна проверяться отдельно в ЛР2; CI пока не настроен.
