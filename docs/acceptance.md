# Приёмка первой версии

Перед демонстрацией выполните README и обязательные проверки. Для сценария нужны две обычные учётные записи и оргкомитет, созданный CLI. Не используйте настоящие персональные данные в учебных скриншотах.

1. Откройте `/`, зарегистрируйте первого участника и войдите. Подайте непустую тему: заявка имеет статус new и появляется в «Мои заявки». Выйдите.
2. Войдите вторым участником: чужая заявка отсутствует. В Swagger попытайтесь создать заявку с participant_id первого участника — 403; без токена — 401.
3. Войдите оргкомитетом: видны обе учётные записи через допустимые запросы профиля и все заявки. Создайте взнос 1500.00 через интерфейс или Swagger. Попробуйте POST /fees/{id}/pay, пока заявка new — 400.
4. Измените статус заявки на accepted и отметьте оплату — paid и заполненное paid_at. Повторите запрос: paid_at сохраняется. Попытка сменить статус на rejected — 400.
5. Проверьте ошибки: пустая тема, неверный email, пароль короче 12, отрицательная сумма и 1.001 — 422; повторный email — 400; неверный пароль — 401.
6. Перезапустите процесс приложения с той же DATABASE_URL: пользователь, заявка и оплата сохраняются. `/health` возвращает ok, `/ready` — ready, `/version` — 0.1.0.
7. Выполните `git check-ignore .env confmanager.db`: оба пути игнорируются. `git ls-files .env confmanager.db` ничего не выводит. Просмотрите diff и отсутствие секретов в коммитах.
8. Покажите GitHub issue, ветку, несколько коммитов, PR с результатами проверок, слияние и тег. Покажите два родителя демонстрационного merge и документ конфликта. Если удалённые объекты ещё не опубликованы, этот пункт не выполнен.

Преподаватель принимает тему, ТЗ и результат на защите. Этот файл задаёт порядок показа и не утверждает, что приёмка уже состоялась.
